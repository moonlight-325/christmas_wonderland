### 제거된 v1.5.0~v1.9.x 쌓인 눈 로직 (v1.4.0 에 없음)
- 열별 흐름 속도(`Pile.flow`, `_step_flow`): 관성/마찰/연쇄 충돌/퍼짐
- 커서가 눈을 공중으로 퍼올리는 `_add_loft` / `_loft_acc`
- 높이 상한 제거(`relax(INF)`)와 `_land` 의 `min(per, cap - h)` 보정
- 덩어리 착지 시 튀어 오름(`collision`) 과 연쇄 충돌(`chain`)
- 열별 숙성도(`Pile.ripe`)·노출면적·두께·밀도 보정 용해 (`snow_density` 포함)

### 최대 축적 높이
- v1.4.0 기존: `max_cells = 2.0 + 눈 축적량/100 x 14.0` (cell, 1 cell = 3px)
- 변경: **정확히 2배** → `(2.0 + 눈 축적량/100 x 14.0) x 2` (눈 축적량 50 에서 9 → 18 cell, 100 에서 16 → 32 cell)
- 적용 위치: `SnowSim.max_cells` 하나가 기준이며 `Pile.maxh` 로 모든 더미(창·작업표시줄·눈사람 머리·바닥)에 전달 → 눈 쌓임, 마우스 밀기, 바람/돌풍, 덩어리 착지, 눈덩이가 가져가기/밀기의 `relax` 가 모두 같은 값을 씀. 충돌 판정 범위(`_refresh_peaks`)도 이 값 기준
- 높이 제한 제거 방식은 사용하지 않음. 더미는 저장 대상이 아니므로 저장/복원 경로는 없음(설정값 `snow.accumulate` 는 그대로)

### 설계 결정 (v1.4.0 과 달라지는 점, 의도적)
1. **넘친 눈**: v1.4.0 은 가장자리/최대 높이를 넘은 눈을 눈송이로 바꿨지만 그 눈송이는 아무 곳에도 쌓이지 않아 사라졌습니다. 이번에는 "창에서 떨어진 눈은 독립 월드로 편입되고 유실되지 않는다"는 요구에 따라 **독립 눈 덩어리**가 되어 떨어지고 닿은 표면에서 v1.4.0 규칙으로 쌓입니다. 단, **바닥**은 더 내려갈 곳이 없으므로 최대 높이 초과분은 버리고 장부에 기록합니다(무한히 되튕기는 것을 막기 위함). v1.4.0 이 버리던 0.3 미만의 위쪽 초과도 같습니다.
2. **v1.4.0 의 흩날림은 눈이 줄어드는 동작입니다**(마우스로 훑을 때 일부, 강풍/돌풍으로 날릴 때). 그대로 복원하되 줄어든 양을 `mass_lost` 장부에 기록해 `mass_balance()` 가 0 으로 맞습니다. 눈이 줄어드는 경우: 온도 융해 / v1.4.0 흩날림 / 바닥 최대 높이 초과 / '눈 청소'.
3. **공중 눈송이에 대한 마우스 반응**(`_cursor_push`)은 "내리는 눈"이므로 v1.9.5 그대로입니다. 쌓인 눈을 미는 `_cursor_plow` 만 v1.4.0 입니다.
4. **설정창**: v1.5.0 전용이던 6개 슬라이더(눈더미 반응 강도·압축/퍼짐·관성·마찰력·충돌 강도·연쇄 충돌)는 지금 물리에서 쓰이지 않아 비활성(회색)으로 표시합니다. 값은 삭제하지 않고 그대로 보관하며 설정 키·저장 형식은 그대로입니다.

### 관찰 사항 / 미해결
- **보관함(`_reservoir`) 일시 급증**: 극단적 부하(창 10개 + 커서 상시 이동 + 30분)에서 덩어리 한도(`MAX_PARCELS`)를 넘은 눈이 보관함에 한때 약 4만 건까지 쌓였다가(24분 시점 2.9만) 다시 줄었습니다. 유실은 없고(장부 일치) 메모리도 평탄하지만, 그동안 해당 눈이 늦게 떨어질 수 있습니다. v1.9.5 의 설계를 그대로 두었습니다. 필요하면 보관함 항목 병합을 후속으로 검토할 수 있습니다.

### Stage 7 추가 — 스노우볼 메이커 창 크기 고정
스노우볼을 만들 때 안쪽 내용 크기 때문에 메뉴가 옆으로 밀리던 문제. 원칙: **실행 중 창 크기는 절대 바뀌지 않는다.** 창 레이아웃이 안쪽 내용 크기로 창을 키우지 못하게 하고(`SetNoConstraint`), 가운데(미리보기) 칸 폭을 고정하고, 오른쪽 설정 칸은 내용 크기를 무시하고 남은 폭만 쓰게 함(넘치면 스크롤). 변경 파일: `widget/snowglobe_window.py`. 미검증: 실제 화면(PySide6 없음).

### Stage 7 추가 — 튕긴 눈 사라짐의 진짜 원인과 렉 진단
- **원인(재현·수정 완료)**: `SnowSim.configure()` 가 호출될 때마다 `_fit_count()` 가 `del flakes[target:]` 로 꼬리쪽 눈송이를 잘랐는데, 커서/바람에 튕겨 난 일시 눈송이(temp)는 항상 목록 꼬리에 붙어 있어서 **설정이 다시 적용되는 순간(자동 날씨가 켜져 있으면 약 10Hz) 통째로 삭제**됐다. 수정: `_fit_count` 가 일시 눈송이를 세지도 지우지도 않음. 일시 눈송이 수 상한은 내리는 눈 수와 분리(`TEMP_MAX`=700). 상한 때문에 못 만든 눈은 사라지지 않고 눈더미에 되돌림(장부 유지). 이전 수정(포물선 비행, 생성 직후 유예 `TEMP_GRACE`, 바닥 착지)도 유지. 옛 코드로 되돌리면 새 회귀 테스트 2개가 실패하는 것을 확인함.
- **렉(창이 열려 있으면 쌓이다가 뚝뚝 끊김)**: 시뮬레이션만으로는 재현되지 않음(눈더미 가득, 창 표면 1개, 커서로 쓸기까지 프레임당 계산 약 0.3~2ms). 그래서 확정 수정이 아니라 **진단 로그**를 추가: 프레임이 늦거나(목표의 2.2배 이상) 계산 25ms/그리기 25ms/창 추적 15ms 이상 걸리면 `app.log` 에 "렉 진단" 한 줄을 3초에 한 번 남긴다(계산·눈더미 그리기·눈송이 그리기·창 추적 시간, 눈송이/눈덩어리/눈더미/창 표면 수). 이 로그를 보면 원인이 계산인지 그리기인지 창 추적인지 구분된다.

### Stage 7 추가 — 스노우볼 메이커 디자인 변경
방향: **글자 버튼이 아니라 그림으로 고른다.** 스노우볼 메이커는 "무엇을 만드는지"가 그림인 도구라서, 이름만 적힌 버튼 격자를 실제 모습 타일로 바꿈.
- 새 위젯 `PixelTile`(`widget/pixel_extra.py`): 그림 타일. 선택됨 = 금색 이중 테두리, 숨김 = 흐리게, 번호 배지. 이름은 툴팁 대신 격자 아래 **한 줄 캡션**에 마우스를 올린/고른 항목이 표시됨.
- 왼쪽: 글자 목록 → **스노우볼 선반**(눈 없는 미니어처 타일 2열, 번호 배지, 숨긴 것은 흐림, 아래 캡션에 선택한 이름).
- 가운데: 미리보기를 **액자**(패널)에 넣음(가운데 칸 폭은 계속 고정).
- 오른쪽: 외형·내부 배경은 실제 렌더러가 그린 썸네일 타일, 장식은 실제 스프라이트 타일(6열).
- 동작·저장 형식·창 크기 고정은 그대로. 변경 파일: `widget/pixel_extra.py`, `widget/snowglobe_window.py`.
- **미검증**: 실제 화면(PySide6 없음). 타일 크기(68×80 / 76×92)와 6열 배치가 오른쪽 칸 폭에 맞는지는 Windows 에서 확인 필요. 모자라면 가로 스크롤이 생김(잘리지 않음).

- 스노우볼 메이커에서만 스크롤바를 숨김(선반·오른쪽 페이지, 가로/세로 모두). 마우스 휠 스크롤은 그대로 동작. 설정창 등 다른 창은 변경 없음. 이 때문에 앞서 넣은 '가로 스크롤 안전망'은 메이커에서 빠짐 — 내용이 칸보다 넓으면 스크롤바 없이 잘릴 수 있으니 Windows 에서 확인 필요.

### Stage 7 추가 — 스노우볼 메이커: 스크롤 없이 잘리지 않게
스크롤 영역을 모두 제거하고(`QScrollArea` 없음) 내용이 창 안에 한 번에 들어오게 맞춤.
- 왼쪽 선반: 소형 타일 3열 x 4줄 = 12개가 스크롤 없이 모두 표시.
- 오른쪽 페이지: 스크롤 없는 일반 페이지. 높이 계산(논리 px, PX=2): 눈 설정 약 472, 꾸미기 약 540, 기본 약 394 ≤ 사용 가능 약 576.
- 가운데: 안내 글을 한 줄 요약으로 줄여 미리보기 아래가 넘치지 않게 함(예전엔 안내 글이 길어 아래가 잘림).
- 창 높이: 열 때 가장 높은 칸의 내용 높이를 재어 한 번만 정하고(화면 높이를 넘지 않음) 이후에는 고정. 실행 중 창 크기는 바뀌지 않음.
- 미검증: 위 높이는 계산값이고 실제 화면은 못 봄. 화면 높이가 낮아 창이 제한되면 아래가 잘릴 수 있음.
