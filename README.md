# Christmas Wonderland v2.0.0 — 픽셀 크리스마스 데스크톱 프로그램

Python + PySide6 기반 Windows 데스크톱 프로그램입니다. 독립적으로 실행되며(통합 런처와 무관), 아래 기능이 하나의 프로그램으로 동작합니다.

## 주요 기능
- **메인 위젯**: 투명 픽셀 위젯(시계·날짜·D-Day), 일반 창 / 항상 아래 창 모드, 빠른 메뉴, 위치·크기 저장
- **데스크톱 눈**: 모든 모니터 전체에 내리는 픽셀 블록 눈. 창 윗면·작업표시줄·바닥에 쌓이고, 질량이 보존되며, 커서·바람·돌풍에 반응하고, 온도에 따라 눈의 양과 높이만 줄어들며 녹음(물은 만들지 않음)
- **눈사람 공방**: 눈덩이를 굴려 눈을 흡수하며 키우고, 조립·장식. 직접 제작(dynamic)은 온도에 녹고 장식용(decorative)은 절대 녹지 않음. 저장·복원
- **스노우볼**: 아이소메트릭 스노우볼 최대 12개, 각각 독립된 내부 물리·외형·배경·장식·눈 설정. 저장·복원
- **날씨 / 자동 날씨**: 수동 설정과 자동 날씨(변수 12개, 변수별 자동/수동, 범위, 프리셋 5종 + 사용자 프리셋). 자동 중 변수를 직접 바꾸면 그 변수만 수동 전환
- **장식 · 전구 · 시계**: 픽셀 장식 배치/편집, 전구 줄, 바탕화면 시계 테마 6종
- **어드벤트 캘린더**: 12월 1~24일 날짜 해금 상자, 퀴즈·소원·잡기 이벤트, JSON 만으로 날짜별 외부 프로그램(`.py`/`.exe`) 연결
- **오디오**: 기본 음악 + 사용자 음악(파일/폴더), 반복·음량, 효과음 5종(눈·바람·눈보라·벽난로·종소리)과 날씨 연동
- **트레이 / 표시 방식**: 트레이와 작업표시줄 표시를 각각 켜고 끌 수 있으며, 트레이 메뉴에서 각 창 열기와 자동 날씨 시작/일시정지/재개 가능
- **일반 설정**: 언어 선택, 트레이·작업표시줄 표시 방식, 성능, 자동 저장 및 백업 관리

## 실행
```
pip install -r requirements.txt
python main.py
```
오류가 나면 `data\app.log` 를 확인하세요.

## 데이터 파일 (`data/`)
| 파일 | 내용 | 손상 시 |
|---|---|---|
| `settings.json` (+ `backups/`) | 설정, 눈사람 | 백업에서 복구, 시작 시 트레이 알림 |
| `snowglobes.json` (+ `.bak`) | 스노우볼 | `.bak` 복구, 없으면 빈 상태 |
| `advent_state.json` (+ `.bak`, `backups/`) | 어드벤트 개봉 기록 | 백업 복구, 손상 파일은 `.corrupt-*` 로 보존 |
| `autoweather_presets.json` | 사용자 자동 날씨 프리셋 | 손상 파일은 `.corrupt-*` 로 보존, 빈 목록으로 시작 |
| `advent_contents.json` | 선물 콘텐츠(편집용 복사본) | 오류 항목은 기본 내용으로 대체 |

저장에 실패하면 설정·스노우볼은 트레이 알림, 어드벤트 개봉 기록은 경고창으로 알립니다.

## 어드벤트 선물에 외부 프로그램 연결
`data/advent_contents.json` 의 날짜 항목에 선택 속성 `action` 을 추가하면 선물 상세 화면에 **선물 실행** 버튼이 나타납니다. 코드 수정은 필요 없습니다.
```json
"action": { "type": "python",     "file": "gifts/christmas_tree/main.py" }
"action": { "type": "executable", "file": "gifts/christmas_tree/christmas_tree.exe" }
```
- 날짜마다 다른 프로그램을 지정할 수 있고, `action` 이 없는 항목은 예전과 똑같이 동작합니다.
- `file` 은 프로그램 폴더(PyInstaller 배포 시 `ChristmasWonderland.exe` 가 있는 폴더, `_MEIPASS` 아님) 기준 상대 경로이며 `gifts/` 안만 허용합니다. 절대 경로·`..`·허용되지 않은 유형/확장자는 거부합니다.
- 프로그램은 별도 프로세스로 시작만 하고 기다리지 않습니다. 같은 선물의 프로그램이 실행 중이면 버튼이 잠겨 중복 실행되지 않습니다.
- 파일이 없거나 Python 을 찾을 수 없으면 경고창으로 안내하고, 성공하면 팝업을 띄우지 않습니다.
- 자세한 내용: `gifts/README.md`

## 눈 오버레이 동작 방식
- 모니터마다 투명 창 1개 (`WindowTransparentForInput` + `WS_EX_TRANSPARENT/LAYERED/NOACTIVATE`)를 바탕화면 바로 위·다른 창 뒤에 둡니다. Z-order 는 프레임마다 검사하지 않고, 활성 창 변경·화면 구성 변경 같은 이벤트 직후와 드문 안전 확인 때만 다시 맞춥니다
- 항상 위 장식 창 위에는 눈을 덧그리는 별도 오버레이(모니터마다 1개)가 장식이 보이는 영역 크기로 열리며, 작업표시줄은 순서 대신 윗선 크기 맞춤과 장식 가리기로 처리합니다
- 창 위치는 `EnumWindows` + DWM 실제 프레임(`DWMWA_EXTENDED_FRAME_BOUNDS`)으로 약 12Hz 추적, 클로킹/최소화/클릭통과 창 제외
- 쌓인 눈은 Z-order 상 그 창보다 위에 있는 창(우리 프로그램 창 포함) 영역을 잘라내고 그려서, 가려진 창 위의 눈은 보이지 않음
- 바람은 설정 탭 외에 작은 독립 창(위젯 메뉴 > 눈 > 바람 조절 창, 트레이 메뉴, 바람 탭 버튼)으로도 조절
- 전체화면 앱이 모니터를 덮으면 그 모니터의 눈을 멈춤 (일반 탭에서 끌 수 있음)
- UAC 보안 데스크톱 등 그릴 수 없는 환경은 예외를 삼키고 계속 실행. 같은 오류가 8회 반복되면 눈 엔진만 중지

## 알려진 한계 / Windows 에서 확인 필요
- GUI(트레이 메뉴, 어드벤트 경고창, 각종 창)와 오디오 재생, Win32 연동은 자동 테스트로 검증되지 않았습니다. 다중 모니터 + 서로 다른 배율, 항상 아래 모드, 작업표시줄 위 눈 쌓임, 전체화면 앱, 음악·효과음은 Windows 실기 확인이 필요합니다.
- 맑음/흐림은 눈의 양으로만 표현되며 화면 색을 바꾸지 않습니다. 자동 날씨는 눈보라·돌풍 켜기/끄기 스위치를 바꾸지 않습니다.
- 음악 파일 추가 시 이미 폴더 목록에 있는 파일도 '추가됨'으로 세어질 수 있습니다(목록에는 중복되지 않음).

- 선물 외부 프로그램 실행(`advent/launcher.py`)은 Linux 에서 로직(경로 검증·Python 탐색·비동기 실행)만 자동 테스트했습니다. Windows 에서 `.exe` 실행, 실제 Python 탐색, PyInstaller 배포 후 `gifts/` 경로, 버튼 화면은 실기 확인이 필요합니다. 콘솔 전용 Python 프로그램은 콘솔 창 없이 실행되므로 창이 있는 프로그램을 연결하세요. Microsoft Store 가 만드는 `WindowsApps\python.exe` 별칭은 자동 탐색에서 제외하므로, Store 판 Python 만 설치한 경우 python.org 판을 설치하거나 `executable` 유형을 쓰세요.

## v2.0.0 — 버전 표기 정렬 및 선택 표시 개선

- **일반 설정 개편**: 기존 성능 탭을 일반 탭으로 변경하고 언어 선택을 이동했습니다. 시스템 트레이 아이콘과 작업표시줄 버튼을 각각 표시/숨김할 수 있으며, 최소 하나는 항상 표시됩니다.
- **영어 UI 레이아웃**: 긴 체크박스 문구와 섹션 제목을 자동 줄바꿈하고 설정 카테고리 폭을 넓혀 글자 잘림을 줄였습니다.
- **성능 최적화(스노우볼)**: 눈송이끼리 충돌 검사(`GlobePhysics._collide`)와 눈송이 갱신 루프를 같은 계산 순서·수식으로 다듬어 흔든 직후 처리 시간을 약 2배 줄였습니다(스노우볼 12개 동시 흔들기, 눈송이 200개: 8.8→4.5ms, 600개: 33.6→16.8ms). 최적화 전 구현과 결과가 비트 단위로 같음을 확인했고(`tests/test_snowglobe_opt.py`가 원래 충돌 구현과 비교), 모양·동작은 바뀌지 않습니다. `tools/bench_snow.py` 는 시간 측정에 `tracemalloc` 이 섞여 수치가 크게 부풀려지던 문제를 고쳤고(시간/메모리 측정 분리), 스노우볼용 `tools/bench_globe.py` 를 추가했습니다. 데스크톱 눈 엔진·눈사람·설정 저장·어드벤트 효과는 측정 결과 이미 충분히 가벼워(프레임 예산의 수 % 이하) 바꾸지 않았습니다.
- **실시간 로그 보기**: 설정 > 일반 탭의 '실시간 로그 보기' 버튼이 별도 콘솔 창에서 `data/app.log` 를 실시간으로 보여 줍니다(`core/logviewer.py`). 앱과 별개 프로세스라 이 창을 닫아도 프로그램은 종료되지 않습니다. Windows 전용.
- **선물 외부 프로그램 실행**: 어드벤트 JSON 의 선택 속성 `action`(`python` / `executable`)으로 `gifts/` 안의 프로그램을 실행합니다(`advent/launcher.py`). `action` 이 없는 기존 JSON 은 변화 없음. 경로 검증(`gifts/` 밖·절대 경로·`..` 차단), 비동기 실행, 중복 실행 방지, 오류 안내 포함.
- **버전 표기**: 프로그램 버전을 v2.0.0으로 정렬했습니다.
- **진단 로그**: 프레임이 늦어지면 `[렉 진단]`, 5초마다 `[프레임 요약]` 을 `data/app.log` 에 남깁니다(`snow/diag.py`, 설정 변경 없음).
- **최소화/닫힌 창 위의 눈**: 창이 사라진 것을 연속 두 번 확인하면 그 창 위의 눈이 곧바로 떨어집니다(`tests/test_minimize_release.py`).
- **눈사람 선택 표시**: 직접 제작한 눈사람의 노란 선택 테두리는 선택 후 10초가 지나면 숨겨지며, 다시 선택하면 표시 시간이 초기화됩니다.

- **미사용 파일 삭제**: `desktop/` 패키지 8개 파일(v1.0~1.1 시절 구형 코드, 어떤 모듈·빌드 스크립트·테스트에서도 import 되지 않음 — import 그래프로 확인)
- **미사용 코드 삭제**: `Pile.height_at`, `SnowSim._trim_extra`, `ground_contains`, `draw_text`, 사용하지 않는 import 14건·지역 변수·인자(`preview_item`, `role_part`), 자동 날씨 탭의 쓰이지 않던 설명 사전. (`decor.sprites` import 는 스프라이트 등록용이라 유지)
- **불필요한 툴팁 삭제**: 시계·장식 창의 '잠김' 호버 툴팁(커서 모양이 같은 정보를 보여 줌). 끄는 동안 값 표시, 화면 밖 보정 안내, 아이콘만 있는 버튼 설명, 색상 칸 이름, 트레이 툴팁은 유지
- **버전/테스트**: `core/version.py` 2.0.0, `tests/test_v200.py` (버전·삭제 항목 검증)

> **현재 코드와 다름**: 이 버전의 '녹은 물(물방울·물줄기·웅덩이)' 기능은 v1.9.1에서 완전히 제거되었습니다. 아래 `snow/water.py`, 물 장부, '녹은 물방울 표시' 옵션, 물 관련 한계 설명은 과거 기록일 뿐 지금은 존재하지 않습니다. 기둥별 용해식(`snow/melt.py`)만 남아 있습니다.
**기존 유지 (건드리지 않음)**: 눈 효과 탭의 온도(℃) 설정, 용해 속도 슬라이더 제거, 자동 날씨의 온도 자동/수동 고정 연동, 눈사람 온도 용해, 기존 온도→기준 용해율 곡선(`physics.melt_rate_for`), 설정/저장 구조, UI. 설정 키 추가 없음 (기존 설정 파일 그대로 호환).

**분석 결과 (v1.5.0)**: 눈 더미는 표면별 열 높이 지도(`Pile.cells`)였고 용해는 모든 열이 거의 같은 식으로 줄어들며 사라졌다(바깥/속 구분 없음, 물 없음). 줄어든 양은 `mass_melted` 장부에만 남았다.

**용해 (`snow/melt.py` 신규)**: 기준 용해율(온도)에 열마다 아래를 곱해 녹인다.
- 노출 표면적: 이웃보다 솟은 옆면이 많을수록(바깥쪽, 가장자리, 뾰족한 곳) 빨리 녹음
- 두께: 얇은 눈이 더 빨리 녹아 먼저 사라짐 (아주 얇게 남은 것만 마저 녹음 — 갑자기 사라지지 않음)
- 밀도: 높이 쌓일수록 눌려 밀도가 올라가고(무게/압력), 조밀할수록 천천히 녹음
- 숙성도(경과 시간): 따뜻한 시간이 흐를수록 눈 속까지 젖어 용해가 가속. 두꺼운 눈은 숙성이 느려 내부는 바깥 용해가 진행된 뒤 순차적으로 녹음. 추우면 서서히 식음
- 젖은 눈은 경사 한계가 줄어 더 쉽게 무너지고, 높이 쌓일수록 무게 때문에 더 쉽게 무너짐 (`Pile.relax`)

**물 (`snow/water.py` 신규)**: 눈 dm 이 녹으면 물 `dm x 밀도` 가 생긴다 (`water_made` 장부). 4가지 상태가 서로 전환된다.
- 물방울: 눈 표면 경사를 따라 굴러감 -> 서로 합쳐지고 -> 물줄기(빠르고 큼) 가 되거나 -> 낮고 평평한 곳에서 멈춰 웅덩이가 됨
- 물웅덩이: 열별 수위(`Pile.wat`). 수위(눈 높이 + 물)를 맞추며 퍼지고, 계속 유입되면 수위 상승. 눈 둔덕 사이/창 위 평평한 곳/바닥에 고임
- 흐르는 물: 이동량이 있는 수위 구간과 물줄기 입자
- 낙하하는 물: 열린 가장자리에서 깊이(`LIP` = 1.2cell) 이상 넘치면 물줄기처럼 떨어져 아래 창/바닥 웅덩이로 합쳐짐
- 창 이동/크기 변경/최소화/닫힘: 눈과 같은 공통 경로(`_move_pile`, `_release_pile`)에서 물도 같이 처리. 빠르게 움직이면 물도 떨어지고, 창이 사라지면 전부 독립 낙하 물이 되어 다른 표면에 고인다 (창 참조 없음)
- 보존: `water_balance()` = 총 물 - (생성 - 증발). 물이 줄어드는 것은 **증발**(눈 용해와 별도 장부 `water_evaporated`, 온도가 높을수록 빠름) 뿐이라 눈/물이 끝없이 늘지 않는다. 물방울 수 한도(900)/낙하 한도(1500)를 넘으면 삭제하지 않고 수위에 합치거나 대기열에 보관
- 물 계산은 눈/렌더링과 분리된 고정 간격(30Hz) 틱. 눈 청소 버튼은 눈만 지움 (물은 증발로만 사라짐), 시뮬레이션 초기화는 둘 다 초기화
- **옵션 '녹은 물방울 표시'** (설정 > 눈 효과, `snow.water_drops`, 기본 켜짐): 끄면 물방울/물줄기 입자를 만들지 않고 녹은 물이 바로 웅덩이 수위로 합쳐진다 (켜져 있던 물방울도 그 자리 수위로 합침, 물의 양은 동일). 웅덩이/넘침/낙하는 그대로 동작. 기존 설정 파일에 키가 없으면 기본값(켜짐)으로 채워진다
- 재동결: `SnowWater._water_freeze_step()` 이 확장 지점으로만 비어 있음 (이번 버전은 구현하지 않음)

**표면 지원 범위 (Win32 로 실제 감지 가능한 것만)**: 창은 사각형으로만 감지된다. 수평 표면(창 윗면, 작업표시줄, 모니터 아래 바닥)에 쌓이고, 가려진 구간은 쌓이지 않는다. 창 모서리/가장자리는 눈이 일정 높이를 넘으면 떨어지고(`EDGE_CAP`) 물은 `LIP` 를 넘으면 떨어진다. 좌우 수직면과 창 아랫면은 눈이 쌓이지 않고 떨어지는 눈/물의 경로일 뿐이다. 운영체제가 경사 표면을 알려 주지 않으므로 경사는 눈더미/눈 위 수위 자체의 기울기로만 존재한다 (경사 창을 감지한다고 가정하지 않음).

**알려진 한계**: 이번 작업은 사용자 요청에 따라 **실행 테스트 없이 문법 검사(py_compile)만** 했다. 용해/물 계수(곡선, `BEAD_VOL`, `LIP`, 이동 속도 등)는 실제로 보면서 조정이 필요할 수 있다. 숙성도/물 열 배열은 열 인덱스에 묶여 있어 눈이 옆 열로 흘러도 같이 이동하지 않는다 (양 보존에는 영향 없음, 눈 질량만 이동). 눈/물 더미는 프로그램 종료 시 저장하지 않는다.

## v1.5.0 변경점 (눈 물리 개선)
**원인 분석 (v1.4.0 까지)**
- 커서로 눈이 사라진 원인: `_cursor_plow` 가 더미 열의 눈을 줄이고 옆 열에는 절반만 더했으며 나머지는 임시 눈송이(`temp`)로 바꿨는데, 그 눈송이는 착지하면 양과 상관없이 제거됐다. 임시 눈송이는 개수 한도를 넘으면 아예 만들지도 않았다. 또 `relax()` 가 `max_cells`(최대 약 16cell=48px)를 넘는 눈을 눈송이 1개로 바꿨다가 버렸고, 커서/충돌 판정도 `max_cells` 높이까지만 검사했다. 그래서 높이 쌓인 눈을 건드리면 사라졌다.
- 창을 움직이면 눈이 붙어 다닌 원인: 더미가 창 키에 종속되어 `set_surfaces` 가 창 좌표로 더미 위치를 통째로 옮겼다(관성 없음). 창을 닫거나 최소화하면 `_drop_pile` 이 40칸만 눈송이로 만들고 나머지를 버렸다. 창 크기가 바뀌면 `resize` 가 열을 최근접 샘플링해 양이 변했다.
- 바람/돌풍으로 날린 눈도 임시 눈송이라 착지 시 사라졌고, 돌풍은 옮기는 눈의 20%를 잃었다.

**구현 (`snow/matter.py` 신규, `snow/physics.py` 수정)**
- 눈의 총량(cell)을 더미 열 + 공중의 눈 덩어리(parcel) + 대기열 + 커서가 퍼올리는 중인 눈으로 센다. 줄어드는 경우는 온도 융해(장부에 기록)와 사용자가 누른 '눈 청소'뿐. `sim.total_mass()` / `sim.mass_balance()` 로 확인.
- 눈더미 열마다 흐름 속도(`flow`)를 두고 커서가 속도·방향에 비례해 힘을 준다. 질량이 이웃 열로 실제 이동하고(운동량 보존), 관성·마찰로 감쇠한다. 더미가 클수록 더 큰 힘이 필요하고, 눌러 퍼지는 효과/가만히 있을 때 천천히 밀림/원형 이동 시 소용돌이(회전력)/빠른 이동 시 덩어리로 퍼올림이 있다.
- 높이 상한 제거: 급경사만 무너지고, '눈 축적량'은 새로 내리는 눈이 더하는 양의 한도로만 쓰인다. 충돌 판정은 실제 가장 높은 더미 기준, 렌더링도 실제 높이 기준으로 컬링한다.
- 창과 눈 분리: 창이 이동하면 눈은 관성으로 뒤처지고(미끄러짐), 속도·가속도가 한계를 넘으면 눈이 덩어리가 되어 떨어진다. 창 가장자리를 끌어 크기를 바꾸면 눈은 제자리를 유지한다. 최소화/닫힘(연속 2회 목록에서 빠짐)이면 더미 전체가 기존 위치·속도를 가진 덩어리가 되어 낙하해 다른 창 또는 모니터 바닥에 쌓인다. 복원돼도 눈이 복제되지 않는다.
- 모니터 아래쪽 가장자리가 바닥(`("ground", n)`)이 되어 떨어진 눈을 받는다 (새로 내리는 눈은 기존처럼 바닥에 쌓이지 않음).
- 설정창 '눈 물리' 탭 추가 (`physics.*`, 모두 0~100): 커서 속도 힘 증가, 눈송이/눈더미 반응, 회전력, 압축·퍼짐, 관성, 마찰력, 충돌 강도, 연쇄 충돌, 창 이동 시 미끄러짐/낙하 민감도. 기존 `weather.cursor_*` 설정과 온도 용해·자동 날씨는 그대로 동작한다.
- 알려진 한계: 이번 버전은 사용자 요청에 따라 문법 검사(py_compile/pyflakes)만 했고 실행 테스트는 하지 않았다. `tests/test_snow_physics.py`(질량 보존, 밀기, 소용돌이, 창 이동/최소화/닫힘, 대량 장시간)를 작성해 두었으니 Windows 에서 `python -m unittest tests.test_snow_physics` 로 확인해 주세요. 눈 더미는 프로그램을 끌 때 저장하지 않는다(설정만 복원). 닫힌 창의 눈은 창 개수와 무관하게 덩어리가 되며, 매우 많은 눈은 덩어리 한도(4000) 초과분을 대기열에 보관했다가 순차적으로 내보낸다.
